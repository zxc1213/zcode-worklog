# WorkLog 需求文档（REQ）

> 版本 v0.1 · 2026-10-31 · 维护约定：每个里程碑评审后更新本文档并在文末记录变更；需求编号 REQ-Xn 一旦分配不复用。
> 配套设计见 `docs/design.md`；已交付功能设计见 `docs/todo-v2-design.md`。

## 1. 愿景与定位

把 WorkLog 从「工作日志插件」升级为**本机工作知识中枢**：

```
采集 Collect  →  组织 Organize  →  提炼 Distill  →  交付 Deliver
(AI对话/目录/git/     (统一条目/日历/      (总结/推荐/         (报告/待办/
 外部系统)             知识图谱)            提示词模板)          回写外部)
```

原则：**本地优先**（数据不出本机，除显式 AI 调用）、**只读优先**（外部对接先读后写）、**可解释**（推荐/总结可溯源到条目）、**零负担**（自动化为主，手动为兜底）。

## 2. 用户与场景

Ray：单人使用，本机多 AI 工具（ZCode/DSH/Claude Code/Codex/Gemini…），多项目并行，需要日报/周报/绩效素材，用飞书/禅道/Hermes 协作，希望每天打开就能看到"今天该干什么、昨天干了什么"。

## 4. 功能需求

优先级：P0=本季度必须，P1=次优先，P2=远期。状态：todo/doing/done。

### A 采集 Collect
- **REQ-C1（P0）AI 会话采集**：保持现有 8 类来源扫描；新增定时采集（见 C5）与手动"立即采集"；采集结果写统一条目并保留现有「## AI 会话」日报小节；来源健康视图（每来源：上次扫描时间/文件数/错误）。
- **REQ-C2（P0）AI 工具配置向导**：面板分步向导——选工具类型 → 填/选位置（路径或 URL）→ 校验（读取成功即列出：模型列表、来源文件数、key 掩码显示）→ 应用；支持对已知类型（ZCode/DSH/Claude/Codex/Gemini/自定义）逐个引导；自定义类型允许填 sessionRoots 正则与文件格式说明。
- **REQ-C3（P0）工作目录监控**：scanRoots/docRoots 保留；新增目录条目标注类型（本地/网盘/git），网盘类（OneDrive/坚果云等同步目录）用 mtime+size 指纹增量扫描；监控结果进统一条目。
- **REQ-C4（P1）外部系统对接**：飞书（自建应用 tenant_access_token，只读拉取：机器人所在群消息摘要、知识库/文档变更、多维表格记录、日程）；禅道（REST token，拉取：我的任务/缺陷/需求变更）；Hermes（待接口信息，先用通用连接器承接）；所有对接产出统一条目并可在日报/周报引用。
- **REQ-C5（P0）采集调度器**：任务模型 {id, kind, enabled, intervalHours 或 dailyAt, lastRunAt}；执行载体=SessionStart hook 补偿式（会话启动时把到期任务跑掉）+ 面板手动；运行历史可查；单任务失败不影响其他任务。

### B 组织 Organize
- **REQ-O1（P0）统一条目模型**：entry = {id, source, type, time, title, detail, project?, tags[], ref}；append-only + 指纹（source+nativeId）去重；现有 git/docs/sessions 归档同时产出条目；条目是日历/图谱/推荐的统一数据底座。
- **REQ-O2（P0）日历视图**：面板新增「日历」页签：月视图（默认当月），每格显示当天活动密度（采集条目数/待办完成/是否有归档/报告）；点日期 → 当日详情（归档摘要、AI 会话列表、待办完成、外部条目、当天报告/总结）；可切换查看总结文本。
- **REQ-O3（P1）知识图谱**：实体（项目/人/AI 工具/主题标签/外部系统对象）与关系（提交了/参与了/提及/依赖）；规则抽取为主（git author、项目名、标签、会话归属），AI 抽取可选增强；数据存 data/graph.json；面板「图谱」页签可浏览实体详情与关系列表（v1 列表式 + 简单可视化，不追求力导向大图）；提供 worklog_graph 查询工具。

### C 提炼 Distill
- **REQ-D1（P0）提示词模板系统**：模板 = frontmatter{id,name,scene,system,user} + 正文；场景 scene 枚举（report-daily/report-weekly/report-month/report-quarter/ask/parse/suggest/summarize/custom-*）；变量 {{today}} {{rangeStart}} {{rangeEnd}} {{content}} {{todos}} {{entries}} 等，缺失变量安全置空；模板存 data/templates/*.md，用户可增删改、设为场景默认、导入导出；所有 AI 调用点（润色/问答/parse/suggest/总结）统一走模板引擎。
- **REQ-D2（P1）周期工作推荐**：规则引擎打分（逾期顺延待办 > 外部系统高优/临期任务 > 活跃项目无日志 > 日历临近事项）产出「建议关注」清单；自动注入周报/日卡片，面板可手动刷新；每条建议可标记采纳/忽略，反馈记录用于调整权重（简单计数权重，不引入 ML）。

### D 交付 Deliver
- **REQ-E1（P0）报告融入新数据源**：日/周/月/季/绩效/项目报告自动包含外部条目与推荐小节。
- **REQ-E2（P2）对外回写**：飞书文档/消息发送（周报草稿推送等）；只做显式手动触发。

### E 平台 Platform
- **REQ-P1（P0）配置中心**：设置页重组为：采集来源（目录/AI 工具）+ 连接器（飞书/禅道/Hermes/通用）+ 调度任务 + 提示词模板 + 数据与备份；全部自定义可维护。
- **REQ-P2（P0）数据安全**：key/secret 只在配置文件明文存储、面板/工具回显一律掩码；备份覆盖新增数据文件（entries/graph/templates）。
- **REQ-P3（P1）可维护性**：设置页「诊断」块：各来源/连接器最近一次运行状态、错误信息、缓存大小、一键重扫。
- **REQ-P4（P1）体验**：面板页签重组为 概览/日历/日志/待办/汇报/图谱/会话/设置；操作反馈统一 notice 体系；长操作显示 busy 态。

## 5. 非功能需求

- 性能：SessionStart hook 全部工作 <3s（扫描走缓存）；日历/图谱渲染 500ms 内（分页+缓存）。
- 隐私：条目/总结只存本机；AI 调用仅发送必要摘要片段；密钥不上报。
- 兼容：Windows 优先（用户环境），路径处理兼容大小写与中文。
- 离线：AI 不可用时所有核心功能降级可用（规则推荐/报告照常）。
